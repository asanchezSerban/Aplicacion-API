¿Qué es SignalR?

SignalR es una librería incluida en ASP.NET Core que permite comunicación bidireccional en tiempo real entre servidor y cliente. A diferencia del modelo HTTP clásico donde el cliente siempre inicia la comunicación, SignalR mantiene una conexión persistente que permite al servidor enviar datos al cliente cuando quiera, sin que el cliente lo pida.

HTTP clásico (actual)

Cliente pide → Servidor responde. El servidor nunca puede avisar al cliente de nada. El cliente tiene que preguntar constantemente si hay cambios.

SignalR (tiempo real)

Conexión persistente. El servidor puede enviar datos al cliente cuando quiera. Los clientes reciben cambios al instante sin necesidad de pedirlos.

Internamente SignalR usa WebSockets si el browser los soporta, y cae automáticamente a Long Polling si no. En IIS con Windows es necesario activar la feature de WebSockets explícitamente.

Casos de uso en ClientManager

Actualmente la app no tiene ningún caso de uso que requiera tiempo real. Estos serían los escenarios que lo justificarían:

👥

Múltiples SuperAdmins

Dos admins trabajando a la vez ven los cambios del otro en tiempo real sin recargar.

🔔

Notificaciones push

Un cliente recibe una notificación cuando su empresa es actualizada o se le asigna algo.

📊

Dashboard en vivo

Métricas y estadísticas que se actualizan solas sin intervención del usuario.

📋

Log de actividad

Un registro de acciones que se actualiza en tiempo real mientras otros usuarios operan.

1. Dependencias y librerías

Backend (.NET)

SignalR ya viene incluido en ASP.NET Core — no hay que instalar ningún paquete NuGet adicional. Solo hay que registrarlo en Program.cs.

Solo si en el futuro hubiera múltiples instancias del servidor (escalado horizontal), habría que añadir un backplane de Redis para sincronizar los Hubs entre instancias:
# Solo en escenario de múltiples servidores — no necesario ahora:
cd AplicacionAPI/ClientManager.API
dotnet add package Microsoft.AspNetCore.SignalR.StackExchangeRedis

Frontend (Angular)

Sí hay que instalar el cliente de SignalR para JavaScript:

cd AplicacionAPI/ClientManagerWeb
npm install @microsoft/signalr

2. Cambios en el Backend

2.1 Crear el Hub

Un Hub es la clase central de SignalR — el punto de comunicación entre servidor y clientes. Equivale a un controlador pero para conexiones persistentes en lugar de peticiones HTTP.

📄 NUEVO → AplicacionAPI/ClientManager.API/Hubs/ClientManagerHub.cs
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.SignalR;

namespace ClientManager.API.Hubs;

[Authorize]
public class ClientManagerHub : Hub
{
    // Se ejecuta cuando un cliente se conecta
    public override async Task OnConnectedAsync()
    {
        var role = Context.User?.FindFirst("role")?.Value;

        // Meter al usuario en el grupo de su rol
        // Así podemos enviar mensajes solo a SuperAdmins o solo a Clientes
        if (!string.IsNullOrEmpty(role))
            await Groups.AddToGroupAsync(Context.ConnectionId, role);

        await base.OnConnectedAsync();
    }

    // Se ejecuta cuando un cliente se desconecta
    public override async Task OnDisconnectedAsync(Exception? exception)
    {
        var role = Context.User?.FindFirst("role")?.Value;

        if (!string.IsNullOrEmpty(role))
            await Groups.RemoveFromGroupAsync(Context.ConnectionId, role);

        await base.OnDisconnectedAsync(exception);
    }
}

2.3 CORS para SignalR

✏️ MODIFICAR → AplicacionAPI/ClientManager.API/Program.cs

La configuración CORS actual ya tiene AllowCredentials() que es obligatorio para SignalR. Verificar que está así:

policy.WithOrigins(corsOrigins)
      .AllowAnyMethod()
      .AllowAnyHeader()
      .AllowCredentials();  // obligatorio — sin esto SignalR no funciona con cookies

2.4 Autenticación JWT para el Hub

SignalR no envía cookies en el handshake de WebSocket de la misma forma que HTTP. Hay que configurar el middleware JWT para que también lea el token del query string en el handshake inicial del Hub.

✏️ MODIFICAR → AplicacionAPI/ClientManager.API/Program.cs

Dentro de options.Events en la configuración JWT, reemplazar OnMessageReceived:

OnMessageReceived = ctx =>
{
    // Para peticiones HTTP normales — leer de la cookie
    var cookie = ctx.Request.Cookies["accessToken"];
    if (!string.IsNullOrEmpty(cookie))
    {
        ctx.Token = cookie;
        return Task.CompletedTask;
    }

    // Para SignalR — el token puede venir como query string en el handshake
    var accessToken = ctx.Request.Query["access_token"];
    var path = ctx.HttpContext.Request.Path;
    if (!string.IsNullOrEmpty(accessToken) && path.StartsWithSegments("/hubs"))
        ctx.Token = accessToken;

    return Task.CompletedTask;
}

2.5 Crear el NotificationService

Para no acoplar los servicios de negocio directamente al Hub, se crea una capa de abstracción — INotificationService. Esto también facilita el testing (se puede mockear fácilmente).

📄 NUEVO → AplicacionAPI/ClientManager.API/Services/INotificationService.cs
namespace ClientManager.API.Services;

public interface INotificationService
{
    Task NotifyCompanyCreatedAsync(object company);
    Task NotifyCompanyUpdatedAsync(object company);
    Task NotifyCompanyDeletedAsync(int companyId);
    Task NotifyUserCreatedAsync(object user);
    Task NotifyUserDeletedAsync(int userId);
}
📄 NUEVO → AplicacionAPI/ClientManager.API/Services/NotificationService.cs
using ClientManager.API.Hubs;
using Microsoft.AspNetCore.SignalR;

namespace ClientManager.API.Services;

public class NotificationService : INotificationService
{
    private readonly IHubContext<ClientManagerHub> _hub;

    public NotificationService(IHubContext<ClientManagerHub> hub)
    {
        _hub = hub;
    }

    public async Task NotifyCompanyCreatedAsync(object company)
        => await _hub.Clients.Group("SuperAdmin").SendAsync("CompanyCreated", company);

    public async Task NotifyCompanyUpdatedAsync(object company)
        => await _hub.Clients.Group("SuperAdmin").SendAsync("CompanyUpdated", company);

    public async Task NotifyCompanyDeletedAsync(int companyId)
        => await _hub.Clients.Group("SuperAdmin").SendAsync("CompanyDeleted", companyId);

    public async Task NotifyUserCreatedAsync(object user)
        => await _hub.Clients.Group("SuperAdmin").SendAsync("UserCreated", user);

    public async Task NotifyUserDeletedAsync(int userId)
        => await _hub.Clients.Group("SuperAdmin").SendAsync("UserDeleted", userId);
}

Registrar en Program.cs:

builder.Services.AddScoped<INotificationService, NotificationService>();

3. Cambios en el Frontend

3.1 Crear SignalRService

📄 NUEVO → AplicacionAPI/ClientManagerWeb/src/app/services/signalr.service.ts
import { Injectable, inject, OnDestroy } from '@angular/core';
import * as signalR from '@microsoft/signalr';
import { Subject } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class SignalRService implements OnDestroy {
  private connection: signalR.HubConnection | null = null;

  // Subjects para cada tipo de evento del servidor
  readonly companyCreated$ = new Subject<unknown>();
  readonly companyUpdated$ = new Subject<unknown>();
  readonly companyDeleted$ = new Subject<number>();
  readonly userCreated$    = new Subject<unknown>();
  readonly userDeleted$    = new Subject<number>();

  async connect(): Promise<void> {
    if (this.connection?.state === signalR.HubConnectionState.Connected) return;

    this.connection = new signalR.HubConnectionBuilder()
      .withUrl('http://localhost:5000/hubs/clientmanager', {
        withCredentials: true           // enviar la cookie accessToken
      })
      .withAutomaticReconnect()         // reconectar automáticamente si se cae
      .build();

    // Registrar handlers para cada evento del servidor
    this.connection.on('CompanyCreated', data => this.companyCreated$.next(data));
    this.connection.on('CompanyUpdated', data => this.companyUpdated$.next(data));
    this.connection.on('CompanyDeleted', id   => this.companyDeleted$.next(id));
    this.connection.on('UserCreated',    data => this.userCreated$.next(data));
    this.connection.on('UserDeleted',    id   => this.userDeleted$.next(id));

    await this.connection.start();
  }

  async disconnect(): Promise<void> {
    await this.connection?.stop();
    this.connection = null;
  }

  ngOnDestroy(): void {
    this.disconnect();
  }
}

3.4 Suscribirse en la lista de empresas

✏️ MODIFICAR → AplicacionAPI/ClientManagerWeb/src/app/pages/companies/company-list.ts
private readonly signalr    = inject(SignalRService);
private readonly destroyRef = inject(DestroyRef);

ngOnInit(): void {
  this.signalr.companyCreated$
    .pipe(takeUntilDestroyed(this.destroyRef))
    .subscribe(company => {
      this.companies.update(list => [...list, company as Company]);
    });

  this.signalr.companyUpdated$
    .pipe(takeUntilDestroyed(this.destroyRef))
    .subscribe(company => {
      this.companies.update(list =>
        list.map(c => c.id === (company as Company).id ? company as Company : c)
      );
    });

  this.signalr.companyDeleted$
    .pipe(takeUntilDestroyed(this.destroyRef))
    .subscribe(id => {
      this.companies.update(list => list.filter(c => c.id !== id));
    });
}

4. IIS — Activar WebSockets

IIS no tiene WebSockets habilitados por defecto. Hay que activarlos manualmente:

Opción A — Panel de control

Panel de control → Programas → Activar o desactivar características de Windows:

Internet Information Services
  └─► Servicios World Wide Web
        └─► Características de desarrollo de aplicaciones
              └─► ✓ Protocolo WebSocket  ← marcar esta casilla

Opción B — PowerShell (administrador)

Enable-WindowsOptionalFeature -Online -FeatureName IIS-WebSockets
Tras activar WebSockets es necesario reiniciar IIS: iisreset

7. Cómo probar que funciona

  1. Abrir la app en dos browsers distintos (o dos ventanas en incógnito) con el SuperAdmin logueado en ambos
  2. En uno crear, editar o borrar una empresa
  3. En el otro la lista debería actualizarse automáticamente sin recargar
  4. También se puede verificar en las DevTools → pestaña Network → buscar una conexión WebSocket a ws://localhost:5000/hubs/clientmanager
